# ComfySilly 0.4.0 — 自动对话记忆

## 使用

1. 在「设置 → 模型与连接」保存聊天/记忆模型的连接，记忆可使用单独的便宜模型。
2. 在新增的「设置 → 自动记忆」启用并选择连接，保存设置。默认不自动启用，避免未经确认产生额外费用。
3. 正常聊天即可。回复完成后后台自动整理；打开已有长对话时会从头分批补齐。
4. 对话顶部「对话记忆」可查看摘要、事实、重要事件、未完成事项与来源消息，也可修正、重试、暂停、清空重建。
5. 新版本窗口标题与设置关于页均为 **0.4.0**。安装包在 `releases/0.4.0/`。

## 行为与边界

- 仅使用已配置的 LLM，通过原有 Rust 提供商模块支持 OpenAI 兼容、Anthropic、Gemini 协议；无向量模型、embedding API 或外部记忆数据库。
- 记忆保存于角色库 JSON 内各自 `sessions[].memory`，不是全局变量，也不是世界书。与会话一起持久化、导出、删除。
- 同卡新对话从空记忆开始；不同卡不共享；只有用户主动创建历史分支时复制**分叉之前有效**的快照，后续独立。
- 后台整理一个任务、逐批提交，当前回复优先。切换对话、关闭聊天、开始生成、暂停记忆或修改配置时取消当前任务。重新进入时自动续做。
- 原始消息不删除。只有被成功摘要覆盖的前缀可以不再发送原文；最近消息和未覆盖的中间消息始终保留。单条超长消息分片续读，不直接截断丢弃。
- 自动整理只使用到最后一条完整 AI 回复；中断的半条回复不立即记成已完成剧情。
- 通过消息 ID、角色、署名及内容指纹验证覆盖范围；编辑、脚本修改、删除、切换回复变体后，失效摘要不参与生成。保留最近 8 个记忆检查点；更早位置无有效检查点时从原文重建，避免未来记忆污染。
- 严格解析完整 JSON、字段、数量、长度、来源消息 ID。不执行模型输出，不接受无效 JSON 推进覆盖游标。失败最多自动重试两次（30 秒间隔），之后可手动重试。
- 不改变用户原始角色设定、世界书、预设顺序、显示正则或插件变量。自动记忆是单独的提示词块，世界书仍使用原来的最近历史进行关键词匹配。
- 不向沙盒 iframe 广播记忆，不新增后台角色卡 iframe。仅记忆变更不触发角色前端完整快照广播，也不重复复制脚本变量检查点。
- 启用记忆时，如果未整理的内容或固定提示词仍超出模型预算，会报告错误并保留消息，而不是悄悄删除未记住的历史。可等待整理、调整上下文、缩短固定设定或暂停本对话记忆；关闭记忆后恢复已有的历史裁剪策略。
- 摘要是有损压缩，不保证模型永不遗漏/幻觉，也不等于无限上下文。可查看来源、修正或从原文重新整理。摘要品质、延迟和费用取决于所选模型；已发出的请求即使取消，也可能产生提供商费用。
- 此版只自动整理正在打开的会话，不在关闭应用后运行，也不扫描整个角色库产生费用。

## 默认参数

| 参数 | 默认值 |
|---|---|
| 自动记忆 | 关闭（一次配置启用后自动运行） |
| 记忆连接 | 跟随当前聊天连接，可指定独立连接 |
| 整理频率 | 每 1 轮完整回复 |
| 最近原文 | 12 条消息 |
| 每批读取 | 16000 字符，最多 16 条/批 |
| 整理输出 | 4096 tokens |
| 记忆注入 | 最多 12000 字符，并受当前输入预算限制 |

## 测试

- `npm test`：包含新增记忆纯逻辑测试：隔离、持久化往返、变体失效、历史分叉、超长消息逐字续读、未处理历史保留、JSON 校验、提示词注入及世界书匹配独立。
- `npm run test:memory`：使用 Edge 无头运行实际 React 组件和明确的 IPC fixture；长历史自动分批、聊天模型与记忆模型分离、发送注入、重启持久化、暂停、无效 JSON、重试、前台取消后台、设置分类。
- `npm run test:ui`、`npm run test:studio`、`npm run test:history`：现有交互卡、变量/事件、历史编辑重生成、角色书架、世界书、身份、设置回归。
- `node tests/chat-controls.smoke.mjs`：预设切换、旧预算迁移、信任持久化、正则前端、当前消息同步读取。旧测试已同步移除对早先取消的重复「生成参数」按钮的依赖。
- `cargo test --manifest-path src-tauri/Cargo.toml --lib`：记忆请求权限与模型配置独立性、三种协议、真实本地 HTTP/SSE 分片、存储原子性、密钥保护等。
- UI 测试使用 fixture，不读写用户卡片/聊天或真实 Key，不代表已验证任意第三方模型的摘要质量；未自动使用用户真实 API 扣费测试。

开发机运行 UI 测试需要 Playwright 和 Edge；可用 `PLAYWRIGHT_MODULE_DIR` 指定已有 Playwright 所在的 node_modules 目录。
